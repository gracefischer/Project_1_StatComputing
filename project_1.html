The change that occurs when selecting a different number of bins is that the number of bars on the histogram change, when breaks = 10, theres 10 bars on the histogram across the x axis. When breaks = 15, theres 15 bars on the histogram across the x axis and so on. In my opinon, the one that looks the best is when breaks = 10. Typically, a histogram has all bars touching, and when we increase to bin = 15 , the space between and roughly 3.3 drops to 0 or so small we cannot see it visually. The same problem occurs in bin = 20. When we make it to bin = 25, there is so much gapping between the bins, the histogram takes the shape of a bar chart, and loses its shape completely. Additionally, throughout all bin varations, the negative skew (or left skew) remains clear, so we are able to draw relatively the same conclusions like mean < median < mode. Though bin = 15 had advanatges like providing more specific data, I think that what it adds does not outweigh the benefits of bin = 10.

Sources I used to help me complete this: https://ggplot2.tidyverse.org/reference/geom_jitter.html

  1. Creating link between color to country_of_bean_origin here is not good because with so many countries it is hard to memorize, however, this could be good to use in in a visualization with a low number of categories, to keep the number of colors low and easy to remember, making it distinct.
  2. Sizing by rating in this graph is slightly redundant since rating is shown on y axis, however, in a good visualization using a different variable would make it more informative and useful.
  3. Using geom_jitter allows overlapping points to not be on top of one another so they can be seen better, but here there is a heavy seperation because of the data so it can misrepresent the data, making it look more spread out than it really is. In a good visualization, when used carefully, it can be useful.
  4. Changing the shape of the points can be useful in a good visualization, like using high contrast shapes that are easy to read, even changing them to represent different categories. Here to make a bad graph I chose shapes that were intentionally difficult to read and would overlap because of aforemenitoned modifications, to prove my point.
  5. Fitting the lm line in this case makes the slope meaningless since it is categorical. In a good visualization, a trendline would fit the data and use loess or whatever shape would meet it. I had to add the aes line to make it show up.
  6. Making the line as thick as it is draws attention away from the data points where the line is suppose to enhance the data, not be a focal point. In a good graph, it would be subtle and help guide the viewer across the data, not distract.
  7. Faceting percent groups an using scale = free lets the axis range be independent on each of the panels. This makes it easy to misjudge, since they are all measuring the same thing. To use this in a good visualization, all scales would be the same or scale = free would be used when the range is unrelated to the others.
  8. This is not much of a modification but i felt it should be included. The use of labels, titiles, subtitiles, and captions should be meaningful in a good visualization so the viewer can figure out what is going on.
  9. Using panel and plot colors that are clashing is an eye-sore and distracting. In a good visualization, we can use differeny colors to make it interesting, but still neutral and low contrast so that the data remains the focal point, and easy to read.
